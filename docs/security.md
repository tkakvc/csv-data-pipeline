# セキュリティレビュー

設計を固める前の段階で、実務のセキュリティレビューで指摘が入りそうな点を自分で洗い出し、対応方針を設計に反映した記録。対応方針の詳細は [architecture.md](./architecture.md) 4章を参照。

---

## 指摘一覧

| No | 重大度 | 指摘内容 | 対応方針 |
|---|---|---|---|
| 1 | 高 | 署名付きURLの保存先パス（S3キー）をクライアントの申告に依存させると、他人のファイルを上書き・閲覧できてしまう | [architecture.md](./architecture.md) 4-2 |
| 2 | 高 | CSV→SQL変換でSQL文字列を組み立てると、SQLインジェクションの温床になる | [architecture.md](./architecture.md) 4-3 |
| 3 | 中 | RDSの認証情報（パスワード）の管理方法が未定義。環境変数への平文埋め込みのリスク | [architecture.md](./architecture.md) 4-4 |
| 4 | 中 | S3バケットの基本設定（パブリックアクセスブロック・暗号化・バージョニング）が未定義 | [architecture.md](./architecture.md) 4-5 |
| 5 | 中 | 署名付きURLの有効期限が長すぎると、漏洩時の悪用可能時間が延びる | [architecture.md](./architecture.md) 4-6 |
| 6 | 中 | アップロードファイルのサイズ・形式検証が未定義。巨大ファイルや不正形式によるコスト増加・タスク失敗のリスク | [architecture.md](./architecture.md) 4-7 |
| 7 | 低 | S3のCORS設定で`AllowedOrigins`をワイルドカード（`*`）にするリスク | [architecture.md](./architecture.md) 4-8 |
| 8 | 低 | 誰がいつアップロードしたかの監査ログが未設計 | [architecture.md](./architecture.md) 4-9 |

## 各指摘の詳細

### 指摘1（高）：署名付きURLの保存先パスをクライアント任せにしない

- 危険な実装：ブラウザ側が「このファイル名で発行して」と指定した値をそのまま信用してURLを発行する
- 具体的な被害：ログイン済みの利用者が、自分以外の保存領域を指すパスを指定すれば、他人のファイルを上書き・閲覧できてしまう
- あるべき実装：保存先パスは、ログイン時に発行されたトークン（JWT）に入っている本人確認済みの識別子から、発行API（Lambda）自身が組み立てる。クライアントからのパス指定は信用しない

### 指摘2（高）：CSV→SQL変換部分のSQLインジェクション対策

- CSVのセルの値をそのままSQL文に文字列連結すると、悪意のある値（例：`'; DROP TABLE summary; --`）がそのままSQLとして実行されてしまう
- パラメータ化クエリ（プレースホルダを使う書き方）を使っているかどうかは、実装後に必ず自分の目でコードを確認する

### 指摘3（中）：DB認証情報の管理

- LambdaやFargateタスクの環境変数にRDSのパスワードを平文で書くと、タスク定義やログから漏洩するリスクがある
- AWS Secrets Manager（秘密情報を暗号化して保管し、実行時にだけ取得させる仕組み）経由で取得する設計にする

### 指摘4（中）：S3バケットの基本設定

- パブリックアクセスブロックが有効になっているか（誰でもPUTできる状態になっていないか）
- サーバー側での保存時暗号化（SSE-S3など）が有効になっているか
- バージョニング（誤って削除した場合に以前の内容を復元できる設定）が有効になっているか

### 指摘5（中）：署名付きURLの有効期限

- 実際にアップロードにかかる時間に対して、有効期限を必要最小限に絞る（数分程度）
- 有効期限が長いほど、URLが万が一ログや通信経路から漏れた場合に悪用できる時間が延びる

### 指摘6（中）：アップロードファイルの検証

- ファイルサイズの上限（巨大ファイルによるストレージ費用・Lambda実行時間の増加を防ぐ）
- 拡張子・Content-Type・中身の形式チェック（CSVを装った別形式のファイル対策）

### 指摘7（低）：CORS設定

- ブラウザから直接S3にPUTするには、S3バケットにCORS設定（どのサイトからのリクエストを許可するかの設定）が必要
- `AllowedOrigins`を`*`にすると、無関係な別サイトのJavaScriptからもアップロードを試行できてしまう。フロントエンドのドメインのみに絞る

### 指摘8（低）：監査ログ

- CloudTrailのS3データイベントログ、またはLambda側の自前ログで「誰が・いつ・何を」アップロードしたかを追跡できるようにする
