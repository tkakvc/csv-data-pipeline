# 要件定義書

- 関連ドキュメント：技術的な設計は [architecture.md](./architecture.md)

---

## 1. 背景・目的

### 背景

費用（コスト）データは、他部署にあらかじめこちらが指定したCSV形式で提出してもらう運用になっている。届いたCSVをもとに、部門・勘定科目ごとの集計を行う必要がある。

### 目的

CSVをアップロードするだけで、内容の解析・データベースへの取り込み・集計までを自動化する。

---

## 2. システム概要

ユーザーがCSVファイルをアップロードすると、自動的に内容が解析されてデータベースに取り込まれ、集計結果が画面に表示されるシステム。画面は2つ、APIは2つで構成する（詳細は3章）。

---

## 3. 機能要件

| 機能ID | 機能名 | 概要 |
|---|---|---|
| FR-1 | CSVアップロード画面 | ファイルを選んでアップロードするだけの画面 |
| FR-2 | 集計結果表画面 | 集計テーブルの中身をほぼそのまま一覧表示する画面 |
| FR-3 | 署名付きURL発行API | ログイン済みユーザーに対し、S3への一時的なアップロード許可証（署名付きURL）を発行するAPI |
| FR-4 | 読み取り専用API | 集計テーブルから結果を返すだけの、複雑な加工をしないAPI |
| FR-5 | CSV取込・集計処理 | S3にアップロードされたCSVを解析し、生データテーブルへのINSERTと、集計テーブルへのINSERT/UPSERTを行う処理（Lambdaで実装。都度実行、夜間バッチではない） |
| FR-6 | バックフィル（過去データの再集計） | 集計ロジックの修正後、過去のrawデータを全件読み直してsummaryテーブルを作り直す機能。管理者が手動で実行する（詳細は[architecture.md](./architecture.md) 6章） |

---

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| 認証方式 | OIDC（OpenID Connect）による「Googleでログイン」を採用する |
| 認可 | 署名付きURLの発行時、保存先パスはログイン中ユーザーのトークン（JWT）から発行API自身が組み立てる。クライアントからの申告値は信用しない（[security.md](./security.md) 指摘1） |
| データ保護 | S3バケットはパブリックアクセスブロックを有効化し、保存時暗号化・バージョニングを有効にする（[security.md](./security.md) 指摘4） |
| データ保護 | RDSの認証情報はAWS Secrets Manager経由で取得し、平文でコードや環境変数に埋め込まない（[security.md](./security.md) 指摘3） |
| 入力検証 | CSV→SQL変換はパラメータ化クエリを使用し、SQLインジェクションを防ぐ（[security.md](./security.md) 指摘2） |
| 入力検証 | アップロードファイルはサイズ上限・形式（拡張子／Content-Type）を検証する（[security.md](./security.md) 指摘6） |
| 有効期限 | 署名付きURLの有効期限は、実際のアップロードに必要な最短時間（数分程度）に絞る（[security.md](./security.md) 指摘5） |
| 監査性 | 誰が・いつ・何をアップロードしたかを追跡できるログを残す（[security.md](./security.md) 指摘8） |
| 性能・可用性 | 個人利用のポートフォリオ用途のため、大量アクセスや高可用性は要件としない |

---

## 5. スコープ外（意図的にやらないこと）

- 費用明細一覧・明細ドリルダウン画面
- ダッシュボードでの複数種のグラフ表示
- 夜間バッチでの集計（アップロードのたびに都度処理する方式にしたため不要。FR-6のバックフィルは、集計ロジック修正時に管理者が手動で実行するものであり、定期的な自動実行ではない）

---

## 6. 制約条件

- 個人開発・学習目的のポートフォリオプロジェクトであり、チーム開発を前提としたレビュー体制・CI/CDの厳格な運用までは求めない
